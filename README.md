# 용용이네 & 밧디글라 주문 폼

```
index.html (고객 주문, 모바일 웹)  →  Apps Script doPost  →  구글 시트 "주문" (받는 분 한 명 = 한 행)
                                            ├─ 구글 시트 "로그" (들어온 요청 전부: 저장·거절·오류 + 원문)
                                            ├─ 구글 시트 "화면기록" (손님이 어디까지 했는지·화면 오류, 방문당 한 줄)
                                            └─ 매일 17:00 엑셀 메일 (어제 17시~오늘 17시 주문, 없으면 생략)
```

문자 모드(`SMS_ON = true` + 솔라피 키)일 때만: 즉시 알림이 문자로, 06:00 요약 문자, '입금확인' 체크 → 고객 문자.

> `apps-script/`는 git에 올리지 않습니다 (담당자 번호·메일 포함). 실제 코드는 시트의 Apps Script 편집기에 있는 것이 기준입니다.

## 설치 (10분)

1. 구글 시트 새로 만들기 → 확장 프로그램 → Apps Script
   (반드시 **시트 안에서** 열 것. script.google.com에서 따로 만들면 시트를 못 찾아 주문이 저장되지 않음)
2. `apps-script/Code.gs` 내용을 붙여넣고 저장
3. 편집기에서 `setup` 함수 1회 실행 → **권한 허용** → 시트 탭 + 트리거 생성
4. 편집기에서 `test_doPost` 실행 → 로그에 `ok`, 메일함에 `[문자 테스트]` 메일이 오면 정상
5. 배포 → 새 배포 → 웹 앱 → 실행: **나**, 액세스: **모든 사용자** → 배포 → URL 복사
6. `index.html` 상단 `API_URL`에 붙여넣기, `ACCOUNT`에 계좌 입력
7. `index.html`을 GitHub Pages 등에 올리기 (파일 하나라 어디든 됨)

## ⚠️ Code.gs를 고친 뒤에는 꼭 재배포

웹 앱은 **배포한 시점의 코드**로 계속 돌아갑니다. 편집기에서 저장만 하면 반영되지 않아요.

배포 → **배포 관리** → 연필(수정) → 버전: **새 버전** → 배포

- URL이 그대로라 `index.html`은 안 고쳐도 됨
- "새 배포"를 누르면 URL이 바뀌니 주의 (바꿨다면 `index.html`의 `API_URL`도 교체)
- 코드에 메일·문자 같은 새 기능이 들어가면 편집기에서 아무 함수나 한 번 실행해 **권한 허용**을 다시 해야 함.
  승인 전에는 주문이 와도 스크립트가 바로 멈춰서 시트도 비고 메일도 안 옴

## 문자 켜기 (나중에)

0. `Code.gs` → `SMS_ON = true` 로 바꾸고 새 버전 배포
1. solapi.com 가입 → 발신번호 등록 → API 키 발급 → 충전
2. 편집기 → 프로젝트 설정(⚙) → **스크립트 속성**에 `SOLAPI_KEY` / `SOLAPI_SECRET` / `SENDER_PHONE` 추가
3. 세 개가 모두 채워지면 문자 발송이 자동으로 켜짐 (재배포 불필요)
4. 편집기에서 `test_sms` 실행 → 담당자 번호로 테스트 문자 확인

`SMS_ON = false`이거나 키가 하나라도 비어 있으면 알림은 `MANAGER_EMAIL`로 메일 발송됩니다.

## 판매 현황 대시보드

`https://yongyong.shop/DASH` (= `minion506.github.io/order_program/DASH`). 주문 폼에서 링크하지 않음, 주소를 아는 사람만 봄.
이름·연락처·주소는 서버에서 빼고 품목별 판매/남은 박스, 일자별 건수·박스·금액만 받아옴.

1. `Code.gs` 맨 끝 `판매 현황 대시보드` 블록을 편집기에 붙여넣고 **새 버전 배포** (편집기에서 `test_summary` 실행 → `ok`)
2. 대시보드를 한 번 열면 시트에 **재고** 탭이 생김 (지금까지 주문된 품목 이름이 미리 채워짐)
3. **남은 박스** 칸에 숫자 입력 → 대시보드 새로고침하면 반영. 품목 이름은 주문 탭 '품목'과 글자까지 같아야 함

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 입금됐는데 주문 탭에 없음 | **로그** 탭에서 이름·번호 검색(Ctrl+F). 결과가 `rejected`·`error`면 손님 화면에 오류가 떴던 주문 → 원문(주소 포함)을 보고 주문 탭에 직접 추가. 로그에도 없으면 서버까지 안 온 것 → 다른 이름으로 주문했는지 손님께 확인 |
| 손님이 "주문이 안 된다"고 함 | **화면기록** 탭 `결과` 열: `연결 불안정 안내`·`전송 중 나감`이면 손님 인터넷 문제, `화면 오류`면 그 줄 `기록`의 오류 문구와 `기기`(아이폰 버전 등)를 개발자에게 전달 |
| 시트가 비어 있고 메일도 안 옴 | 편집기에서 `test_doPost` 실행 → 권한 허용 → `ok`인지 확인 후 **새 버전 배포** |
| `test_doPost`가 "행 추가 실패" | 같은 번호 1분 내 중복 차단에 걸린 것. 1분 뒤 다시 실행 |
| 폼에서 "주문이 접수되지 않았어요" | 편집기 왼쪽 **실행**(≡▶) 메뉴에서 `doPost` 오류 확인 |
| 대시보드가 "불러오지 못했어요" | 대시보드 블록을 붙여넣은 뒤 **새 버전 배포**를 했는지 |
| 주문 메일이 어디로 가는지 | `Code.gs` → `MANAGER_EMAIL` |
| 화면 구석에 `undefined` 같은 글자 | 크롬 확장 프로그램 문제. 시크릿 창에서 안 나오면 무시 |

## 로그 탭

주문 폼에서 서버로 들어온 요청은 결과와 상관없이 한 줄씩 **로그** 탭에 쌓입니다 (탭은 첫 요청 때 자동 생성).

| 결과 | 뜻 |
|---|---|
| 저장 | 주문 탭에 저장됨 |
| 재전송(이미 저장됨) | 응답이 늦거나 끊겨 폼이 같은 주문을 다시 보낸 것. 다시 저장하지 않음 |
| rejected: dup | 같은 번호로 1분 안에 다른 주문 → 손님 화면에 "1분 뒤에 다시" 안내 |
| rejected: soldout:N | 남은 수량 부족 → 손님 화면에 "N박스까지" 안내 |
| rejected: (그 외) | 입력 형식 오류 → 손님 화면에 "접수되지 않았어요" |
| error: … | 서버 오류(락 대기 초과 등). 폼이 알아서 다시 보냄 |

손님 인터넷이 아예 끊겨 서버까지 못 온 요청은 로그에도 없습니다. 시즌이 끝나 주문 기록을 지울 때 로그 탭도 같이 지우세요 (개인정보 포함).

## 화면기록 탭

주문 화면에서 손님이 어디까지 진행했는지와 화면 오류가 방문 한 번당 한 줄로 남습니다. 이름·연락처·주소는 없습니다.
열기만 하고 나간 방문은 남기지 않습니다.

| 결과 | 뜻 |
|---|---|
| 완료 | 주문 접수 완료 화면까지 감 |
| 연결 불안정 안내 | 1분 동안 응답을 못 받아 "한 번 더 눌러 주세요" 안내가 뜸 (다시 눌러 완료하면 `완료`로 바뀜) |
| 거절 (rejected: …) | 서버가 거절 (로그 탭 결과와 같음) |
| 전송 중 나감 | "이대로 주문하기"를 누르고 결과가 나오기 전에 페이지를 닫음 |
| 화면 오류 | 화면에서 JS 오류 → `기록`에 오류 문구, `기기`에 브라우저 정보 |
| 확인 창에서 멈춤 / 입력하다 나감 | 주문하지 않고 나감 (`입력 오류 senderPhone` = 보내는 분 연락처 형식에서 막힘) |

- `기록` 예: `0초 열림 → 12초 주문하기 → 13초 전송 → 33초 응답 20초 응답 없음 → … → 결과 ok`
- 로그 탭과 짝짓기: 로그 탭 `원문`의 `"visit":"abcd1234"` 값을 화면기록 `방문` 열에서 Ctrl+F
- 개인정보 처리방침에 따라 **3개월 지난 줄은 지우세요** (시각 열 기준)
